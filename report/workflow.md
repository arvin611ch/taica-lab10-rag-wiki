# 流程設計與反思

這頁回答作業的步驟三與步驟四：資訊怎麼被取得、整理、檢查，再變成簡報；哪些步驟會重複、哪裡會重新生成；以及實際跑過一次之後，哪個節點最常出錯、我把檢查往前移到哪裡、流程因此改了什麼。所有數字都來自 [執行紀錄](runs/index.html)。

| 節點 | 誰做 | 輸入 → 輸出 | 檢查什麼／不通過回到哪 |
| --- | --- | --- | --- |
| ① 取得資料 | 程式 `fetch_sources.py` | 網址 → 純文字＋SHA-256 | 原始資料只讀不改 |
| ② 討論重點 | AI 提案、使用者選 | 原文 → 每篇要強調的重點 | 討論內容照實寫進 [討論紀錄](wiki/discussions/2026-11-23-ingest-discussion.html) |
| ③ 寫入一頁 | AI | 原文＋重點 → 來源頁（主張＋逐字證據）或概念頁 | — |
| ④ 單頁檢查 | 程式 `lint_wiki.py --page`＋AI 主張審查 | 剛寫好的那一頁 | 證據是否逐字出自原文、數字是否都在證據裡、連結；中文是否比英文證據說得更強 → 回 ③ |
| ⑤ Wiki 檢查 | 程式 `lint_wiki.py` | 整個 Wiki | 孤兒頁、目錄、log 格式、每篇來源都被用到 → 回 ③ |
| ⑥ 查詢 Wiki | AI | 學習目標 → 讀目錄、總覽、概念頁 | 找不到支撐的內容 → 回 ① 補資料 |
| ⑦ 整理大綱 | AI | → `deck/outline.json`，每點附主張編號或標成比喻／例子／本專案說明 | — |
| ⑧ 大綱檢查 | 程式 `check_deck.py --content-only` | 大綱 | 出處、數字、名詞先定義後使用、目標覆蓋、每頁 ≤4 點每點 ≤40 字 → 回 ⑦ |
| ⑨ 產生簡報 | 程式 `render_deck.py` | 大綱 → HTML 簡報＋存回 Wiki 的對應表 | — |
| ⑩ 畫面檢查 | 程式 `check_deck.py`（無頭瀏覽器）＋AI 看截圖 | HTML | 溢出（含 SVG 文字）、連結與錨點、換頁 → 回 ⑨ 或 ⑦ |
| ⑪ AI 審查 | 兩個沒看過製作過程的 AI | 新手只拿簡報文字；查核員只拿「重點↔主張」 | 新手卡住、答錯 → 回 ⑦；說得比證據強 → 回 ⑦ 或 ③ |
